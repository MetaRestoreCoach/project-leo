# Project LEO — Health Coaching App (MVP1)

> *"Your Health is Your Wealth"*

Project LEO is a cross-platform AI-powered health coaching app built for iOS, Android, and Web. It connects personal health data from wearables and manual logs to deliver personalized, evidence-based coaching plans generated by Claude AI (Anthropic). The app targets users managing chronic conditions — diabetes, hypertension, high cholesterol — using a functional medicine ("food is medicine") philosophy.

Live web app: [project-leo-virid.vercel.app](https://project-leo-virid.vercel.app)

### Design System — Vital Meridian

The app uses the **Vital Meridian** design language — a clinical-aesthetic movement built on a deep near-midnight navy canvas with biometric color semantics:

| Color | Semantic Meaning |
|-------|-----------------|
| Coral | Cardiac / heart rate |
| Electric ocean blue | Oxygen / recovery |
| Emerald | Movement / activity |
| Amber | Nutrition / metabolic energy |
| Violet | Sleep / neural recovery |

Typography pairs an old-style serif (display headings) with a razor-thin geometric grotesque (labels) and monospace (raw data values). Form follows function follows biology.

### Key Architectural Decisions

| Decision | Rationale |
|----------|-----------|
| **Claude runs server-side only** | API key never sent to the client. All AI calls go through Supabase Edge Functions (Deno). |
| **PKCE OAuth flow** | Prevents auth code interception on mobile. Required for public clients (no client secret). |
| **Platform-aware session storage** | `expo-secure-store` on native; synchronous `localStorage` on web (required so the PKCE code verifier is written before the OAuth redirect fires). |
| **Pre-exchange OAuth code before registering auth listener** | `initialize()` in `useAuthStore` calls `exchangeCodeForSession()` when `?code=` is present in the URL before subscribing to `onAuthStateChange`. Without this, `INITIAL_SESSION: null` fires before the PKCE exchange completes, routing the user back to login. |
| **File-based routing (Expo Router)** | Route groups `(auth)`, `(tabs)`, `onboarding` enforce layout isolation and enable deep linking automatically. |
| **Row-Level Security on all tables** | Every Supabase table enforces per-user data isolation at the database layer — no accidental data leaks even with a compromised anon key. |
| **Zustand for global state** | Lightweight, no boilerplate. Auth and onboarding state shared across the route tree. |
| **Onboarding welcome hub** | New users land on `/onboarding/welcome` (not directly on step1). The hub separates optional health data connection from the mandatory profile wizard so neither step blocks the other. |

### Auth Flow (3 screens)

**Login**
- Google OAuth button (Continue with Google)

**Sign Up**
- Google OAuth button (Sign up with Google)

- Email input → Send Reset Link → success confirmation state

### Onboarding (5 screens — routes under `/onboarding/`)

| Route | Screen | Purpose |
|-------|--------|---------|
| `welcome` | Welcome Hub | Entry point for all new users. Two sections: (1) **Connect Health Data** — optional; shows Apple Health (iOS) or Google Fit (web/Android) with Connect / Skip; (2) **Set Up Your Profile** — mandatory CTA navigating to step1. |

| `step3` | Your Goals | Multi-select chips: Reverse Diabetes, Lower BP, Lower Cholesterol, Lose Weight, Improve Energy, Better Sleep, Eat Healthier, Build Strength |
| `step4` | Preferences | Dietary chips + Activity level (Sedentary → Very Active). Saves profile and sets `onboarding_completed = true`. |

### Main App — 4 Tabs

**Dashboard (Home)**
- Personalized greeting + health score (0–100, based on last 7 days)
- Weekly AI coaching summary (diet + exercise tip) with link to full plan
- 6 health metric cards in 3×2 grid: Blood Glucose, Blood Pressure, Steps, Water, Sleep, Weight — each with icon, value, unit, trend indicator
- Goals progress bars with percentage completion, color-coded by goal type
- Today's meals: Breakfast / Lunch / Dinner with calorie counts and log/check status

**Log**
Three-tab interface for data entry:
- *Meal* — meal type chips (Breakfast, Lunch, Dinner, Snack), free-text description, Log Meal button
- *Health Metric* — metric type selector (glucose, BP, weight, steps, sleep, water), value + unit, optional notes
- *Lab Result* — test name, value, reference range, date selector

**AI Coaching**
- Medical disclaimer banner (AI-generated content notice)
- Diet recommendations: title + description + scientific rationale + priority (high/medium/low)
- Exercise plan: activity + duration + rationale
- Supplement suggestions: name + dosage + evidence-based rationale
- Powered by Claude API (Anthropic) via Supabase Edge Function

**Profile**
- Avatar with user initials
- Personal info rows: name, email, age, gender, height, weight
- Health conditions, goals, dietary preferences displayed as chips
- Edit Profile button (inline form)
- Sign Out button

## Environment Variables

```env
# Supabase
EXPO_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=your-anon-key

# Google OAuth (Google Cloud Console)
EXPO_PUBLIC_GOOGLE_CLIENT_ID=your-client-id.apps.googleusercontent.com

# Claude API — set as Supabase secret only, NEVER in client .env
CLAUDE_API_KEY=sk-ant-your-key-here
```

> ⚠️ `CLAUDE_API_KEY` must only be set as a Supabase Edge Function secret (`supabase secrets set CLAUDE_API_KEY=...`). It is never exposed to the client app.

## Setup Guides

### Supabase
1. Create project at [supabase.com](https://supabase.com)
2. Run `supabase/migrations/001_initial_schema.sql` in SQL Editor
3. Copy Project URL + anon key → `.env`
4. Enable Google OAuth: **Authentication → Providers → Google**

### Vercel (Web)
1. Import repo at [vercel.com](https://vercel.com)
2. Build command: `npx expo export --platform web` | Output: `dist`
3. Add env vars from `.env`
4. Every `git push` to `main` auto-deploys

### Claude API
1. Generate key at [console.anthropic.com](https://console.anthropic.com)
2. `supabase secrets set CLAUDE_API_KEY=sk-ant-...`
3. `supabase functions deploy generate-coaching-plan`

## Roadmap

**MVP1 (Current):** Auth, onboarding, dashboard, manual logging, AI coaching, web deploy

**MVP2:** Apple Health + Strava + Garmin integration, push notifications, data trends

**MVP3:** Human coach marketplace, community features, multi-language, B2B portal

**MVP4:** Motivational interviewing (MI) style onboarding questions to surface intrinsic motivation and readiness to change; Wellness Wheel assessment (8 dimensions: physical, emotional, social, occupational, spiritual, intellectual, environmental, financial) captured during onboarding and visualized as an interactive radar/spider chart on the dashboard; coaching plan aligned to the user's lowest-scoring wellness dimensions

**MVP5 — Subscription Model:**

- **Tier 1 — AI Plan ($9.99/month):** User accepts terms, provides payment details, and subscribes. Access includes full app features + AI chat with coaching goals powered by Claude. No human coach involvement.

- **Tier 2 — Real Coaching (configurable price, default $50–$100/session):** User subscribes to 1 human health coach session per week. Session price is admin-configurable. Coupon/promo code support to apply discounts at checkout. Matched with a certified health coach for live sessions.

- **Subscription infrastructure:** Payment processing (Stripe), terms acceptance flow with timestamp, subscription status gating on feature access, coupon redemption engine, admin dashboard to configure Tier 2 session pricing per coach or globally.
